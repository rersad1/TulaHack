# Volunteerly

**Volunteerly** — это веб-платформа для эффективной координации волонтерской помощи. Система автоматизирует процесс создания заявок, поиска исполнителей и коммуникации между участниками, соединяя тех, кто нуждается в помощи, с теми, кто готов её оказать.

Проект разработан в рамках хакатона **TulaHack** с упором на социальную значимость, безопасность данных и удобство использования.


## Описание и возможности

Архитектура приложения построена на принципах микросервисного взаимодействия, обеспечивая масштабируемость и разделение ответственности между модулями управления пользователями/задачами и системой обмена сообщениями.

### Ключевой функционал

* **Ролевая модель:** Разделение на «Пользователя» (создание запросов) и «Волонтера» (выполнение заявок).
* **Безопасность:** Регистрация с подтверждением email, JWT-аутентификация (Access/Refresh), хеширование паролей (BCrypt).
* **Управление заявками:** Полный жизненный цикл (создание, фильтрация, назначение, завершение).
* **Smart Matching:** Система рекомендаций волонтеров на основе рейтинга и истории задач.
* **Real-time Чат:** Обмен сообщениями между участниками через WebSocket.
* **Рейтинговая система:** Профили участников и оценка качества выполнения.

## Технологический стек

### Backend
Серверная часть реализована на Java 17 и Spring Boot 3.

**Core / Volunteer Service** (Основная бизнес-логика):
* **Frameworks:** Spring Web, Spring Data JPA, Spring Security, Spring Mail.
* **Security:** JJWT (JSON Web Token), BCrypt.
* **Utils:** Lombok, Validation API.

**Chat Service** (Микросервис сообщений):
* **Protocol:** Spring WebSocket (STOMP).

### Frontend
SPA приложение на React.js.
* **Routing:** React Router v6.
* **HTTP Client:** Axios (с интерцепторами для JWT).
* **Styling:** Tailwind CSS.

### Инфраструктура
* **DB:** PostgreSQL (Prod), H2 (Dev/Test in-memory).
* **Containerization:** Docker & Docker Compose.
* **Build Tool:** Gradle.

## Архитектура

Система разделена на независимые модули для повышения отказоустойчивости:
1.  Сервис обработки заявок и пользователей.
2.  Сервис обмена мгновенными сообщениями.
3.  Клиентская часть (Single Page Application).

## Конфигурация

Основные настройки находятся в файле `application.properties`.

| Параметр | Описание |
| :--- | :--- |
| `spring.datasource.*` | URL, username и password для подключения к БД |
| `spring.mail.*` | Настройки SMTP сервера для email-уведомлений |
| `jwt.secret` | Секретный ключ для подписи токенов |
